# NutriAdvisor

**AI-помощник по питанию** — мобильное приложение (PWA + Android APK) для персонализированного анализа и коррекции питания.

Приложение помогает скорректировать питание исходя из ваших целей (похудение, набор массы, улучшение сна и др.), анализирует съеденные продукты через текст или фото, даёт рекомендации через AI-ассистента, ведёт каталог продуктов и блюд, журнал питания и дневник самочувствия.

> **Локальное хранение** — все данные и история хранятся локально на устройстве (IndexedDB). Приложение работает и в полностью автономном режиме с локальными LLM (Ollama, llama.cpp).
>
> **Опциональный сервер** — для монетизации и управления провайдерами доступен серверный прокси (`server/`), который маршрутизирует запросы к LLM, управляет биллингом и обеспечивает бесплатный доступ через встроенные модели.

## Возможности

### LLM и анализ
- **Конфигурируемые LLM-провайдеры** — OpenAI, OpenRouter, Alibaba DashScope, Ollama (локальный), llama.cpp, произвольные. Добавляйте, редактируйте, удаляйте провайдеры и переключайтесь между ними.
- **Списки моделей** — сохранённый перечень моделей для каждого провайдера для быстрого выбора.
- **Анализ еды по фото** — снимок камеры или выбор из галереи. Vision-модель описывает блюдо, затем AI оценивает КБЖУ с учётом указанных описания и веса порции.
- **Анализ еды по тексту** — введите описание блюда и вес, AI оценит калорийность и макронутриенты.
- **Стриминг ответов LLM** — ответы чата появляются в реальном времени по мере генерации. Кнопка остановки для прерывания генерации.
- **Нативный стриминг в Android** — через собственный Capacitor-плагин `NativeHttpPlugin`, обходит ограничения WebView на CORS и mixed content.
- **10 предустановленных целей питания** — здоровье, похудение, набор массы, набор мышц, сушка, улучшение сна, самочувствие, бодрость ума, энергия, поддержание веса.
- **Пользовательские цели** — создавайте свои цели питания на вкладке профиля.

### Каталог продуктов и блюд
- **Продукты** — справочник отдельных продуктов (яблоко, гречка, миндальный орех и т.д.) с CRUD-операциями.
- **Блюда** — составные блюда из продуктов с указанием граммовок каждого ингредиента (например, «мой чечевичник: гречка 40г + чечевица 60г + 1 яйцо + масло льняное 10г»). Конструирование из каталога продуктов.
- **Компонентный приём пищи** — при добавлении приёма пищи в журнале можно выбирать отдельные продукты и блюда из каталога, задавая вес каждой позиции. Формируется структурированная запись с набором позиций.

### Чат и контекст
- **AI-чат ассистент** — диалоговый интерфейс с контекстными рекомендациями. Автоматически определяет тему сообщения и подбирает системный промпт.
- **Контекст питания в чате** — подключайте к диалогу данные за сегодня, неделю или месяц. AI видит что вы ели и даёт рекомендации с учётом реального рациона.
- **Контекст дневника в чате** — записи дневника (активность, самочувствие, давление) за выбранный период также включаются в контекст AI.
- **Множественные диалоги** — сессии чата с навигацией по датам в боковой панели.
- **Редактирование сообщений** — отредактируйте любое сообщение пользователя и переотправьте диалог с этой точки.
- **Переименование сессий** — двойной клик или кнопка для переименования разговора.

### Журнал питания
- **Журнал с группировкой по датам** — записи группируются по дням с пейджингом для навигации по истории.
- **Структурированные записи** — каждый приём пищи состоит из набора продуктов и/или блюд с указанием граммовок.
- **Редактирование записей** — возможность отредактировать ранее сохранённый приём пищи.
- **Проверка КБЖУ** — после AI-анализа значения калорий, белков, жиров, углеводов можно скорректировать вручную перед сохранением.
- **Предупреждение о неполных данных** — если AI не определил какой-то макронутриент, система уведомит и предложит повторить анализ или заполнить вручную.
- **Выбор даты** — при добавлении записи можно указать любую дату, а не только сегодняшнюю.

### Дневник
- **Три типа записей**: активность (описание + длительность), самочувствие (заметка), измерение давления (систолическое, диастолическое, пульс).
- **Сводка за день** — карточка с итогами по активностям, записям самочувствия и замерам давления.
- **Группировка по датам** с пейджингом для навигации по истории.
- **Интеграция с чатом** — записи дневника автоматически включаются в контекст при обращении к AI-ассистенту.

### Данные и экспорт
- **Экспорт/импорт данных** — полная резервная копия всех данных (провайдеры, профиль, журнал, чат, дневник, каталог продуктов и блюд) в JSON-файл для переноса между устройствами.
- **Профиль пользователя** — параметры тела, уровень активности, ограничения в питании, медицинские заметки.
- **Дашборд** — сводка КБЖУ за день, прогресс по целям, быстрые действия.

### Платформы
- **PWA** — устанавливается через браузер (Добавить на главный экран).
- **Android APK** — сборка нативного приложения через Capacitor (см. раздел «Сборка Android APK»). Собственная иконка приложения.
- **Экспорт в мессенджеры** — отправка данных анализа питания через Android Share Sheet (в Telegram, WhatsApp и др.).
- **Markdown-рендеринг** — ответы LLM отображаются с форматированием (заголовки, списки, таблицы, код, цитаты) без внешних зависимостей.

## Серверный прокси (LLM Proxy)

В директории `server/` находится прокси-сервер на **Go**, который:

- **Проксирует запросы к LLM** — единая OpenAI-compatible точка входа для приложения
- **SOCKS5-прокси через SSH-туннели** — автоматический запуск, health-check, автоперезапуск, верификация external IP
- **Модельная приоритизация с fallback** — приоритет на уровне моделей (не провайдеров): free:31b → free:26b → local → paid:26b → paid:31b. При 429/ошибке попытка повторяется со следующей моделью по приоритету
- **Маршрутизация по алиасам** — `gemma-4`, `gemini-2.5-fp`, `gigachat` — каждый алиас резолвится в список моделей из fallback-цепочки провайдеров
- **Управление конкурентностью** — пулы слотов на каждый провайдер (`max_concurrency`), корректное освобождение при успехе и при ошибке (включая стриминг)
- **Поддержка SSE стриминга** — pass-through потоковой передачи, fallback работает если ошибка до отправки заголовков
- **NuAdvi Proxy как провайдер по умолчанию** — клиентское приложение имеет преднастроенный провайдер `kreagenium.ru/nuadvi` без необходимости ввода ключей
- **Биллинг** (заготовка) — SQLite для балансов, бесплатный tier (3 запроса/день), pay-as-you-go с наценкой
- **Управление секретами** — `.env` файл (не в git), копируется на сервер при деплое, подставляется в `config.yaml` через `${VAR}`
- **Интеграция с cm-server** — создание и проверка платежей через ЮKassa (заготовка)

### Структура сервера

```
server/
├── main.go                  # Точка входа, graceful shutdown, старт прокси-менеджера
├── config/
│   └── config.go            # YAML + env парсер, модельная приоритизация (Priority field)
├── handlers/
│   └── handler.go            # HTTP-эндпоинты, candidate-based fallback loop
├── providers/
│   ├── provider.go           # Интерфейс Provider + TransportSetter
│   ├── openai.go             # OpenAI-compatible адаптер (SSE streaming)
│   └── gigachat.go           # GigaChat OAuth2 адаптер
├── proxy/
│   ├── router.go             # Router, CandidateProvider, Pool (concurrency slots)
│   └── proxyctl.go           # ProxyManager, SSH SOCKS5 tunnel, health-checks, VerifyConnectivity
├── scripts/
│   ├── deploy.sh             # Скрипт деплоя (sync → env → build → restart)
│   └── test.sh               # 9 тест-секций (health, models, chat, stream, concurrency, etc.)
├── config.yaml               # Конфигурация провайдеров, моделей, приоритетов, SOCKS5-прокси
├── .env.example              # Шаблон секретов (OPENROUTER_API_KEY, GIGACHAT_API_KEY)
├── go.mod
└── .gitignore
```

### Деплой сервера

Сервер деплоится на **kreagenium.ru** (порт 3001) через Nginx reverse proxy (`/nuadvi`):

```bash
# Полный деплой (sync → build → restart)
cd server
./scripts/deploy.sh all

# Или по шагам:
./scripts/deploy.sh sync      # Синхронизировать файлы
./scripts/deploy.sh build     # Собрать бинарник на сервере
./scripts/deploy.sh restart   # Перезапустить
./scripts/deploy.sh logs      # Логи
./scripts/deploy.sh status    # Статус
```

Переменные окружения для кастомизации:

| `SSH_PORT` | `22` | SSH порт |

## Сборка Android APK

Приложение можно собрать как нативный Android APK с помощью **Capacitor** — через Gradle из командной строки (без Android Studio) или через Android Studio.

### Требования

- **Android SDK** (установлен и настроен, переменная `ANDROID_HOME`)
- **Node.js** 18+
- **JDK 17+**

> Android Studio не обязателен. Достаточно установить Android SDK командной строки и JDK.

### Быстрая сборка через Gradle (без Android Studio)

**Отладочный APK** (для тестирования):
```bash
npm run apk:debug
```

**Подписанный релизный APK**:
```bash
npm run build:android
cd android && ./gradlew assembleRelease
```

**Релизный AAB** (для Google Play):
```bash
npm run build:android
cd android && ./gradlew bundleRelease
```

Готовые артефакты:
- Debug APK: `android/app/build/outputs/apk/debug/app-debug.apk`
- Release APK: `android/app/build/outputs/apk/release/app-release.apk`
- Release AAB: `android/app/build/outputs/bundle/release/app-release.aab`

Эти команды выполняют всё за один шаг: сборка Next.js → синхронизацию с Android → сборка через `./gradlew`.

Для установки APK на устройство:
```bash
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

### Подпись релизной сборки (APK / AAB)

Подпись настроена в `android/app/build.gradle` → `signingConfigs.release`. Секреты читаются из `android/local.properties` (файл не в git, шаблон ниже) или из переменных окружения. Если ни того ни другого нет — релизная сборка пройдёт без подписи (unsigned).

```properties
# android/local.properties (не коммитится в git)
KEYSTORE_PATH=../../keystore
KEYSTORE_PASSWORD=пароль_от_keystore
KEY_ALIAS=nuadvi
KEY_PASSWORD=пароль_от_ключа
```

Или через переменные окружения:

```bash
KEYSTORE_PASSWORD=... KEY_ALIAS=nuadvi KEY_PASSWORD=... KEYSTORE_PATH=../../keystore \
  ./gradlew assembleRelease
```

#### Добавление ключа в существующий keystore

```bash
keytool -genkeypair \
  -keystore /путь/к/keystore.jks \
  -alias nuadvi \
  -keyalg RSA \
  -keysize 2048 \
  -validity 9125
```

Параметр `-validity 9125` — 25 лет (требование Google Play).

### Сборка через Android Studio

Если предпочитаете Android Studio:

```bash
npm run build:android
npm run open:android
```

Затем в Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.

### Все доступные команды

| Команда | Описание |
|---|---|
| `npm run build:android` | Собрать Next.js + синхронизировать с Android |
| `npm run apk:debug` | Полный цикл: сборка + отладочный APK |
| `npm run apk:release` | Полный цикл: сборка + релизный подписанный APK |
| `cd android && ./gradlew bundleRelease` | Сборка AAB для Google Play |
| `npm run open:android` | Открыть проект в Android Studio |

### Настройка Android-проекта

Файл `capacitor.config.ts` содержит настройки:
- `appId: 'ru.kreagenium.nuadvi'` — идентификатор пакета.
- `webDir: 'out'` — директория со статическим экспортом Next.js.
- `androidScheme: 'https'` — HTTPS-схема для WebView (требуется для camera и других APIs).
- Цвета сплеш-скрина и фона — `#059669` (emerald-600).

#### NativeHttpPlugin
Для корректной работы LLM-запросов из Android APK (обход WebView CORS и mixed content ограничений) используется собственный Java-плагин:
- `android/app/src/main/java/ru/kreagenium/nuadvi/NativeHttpPlugin.java` — HTTP-клиент на `HttpURLConnection` с SSE-стримингом.
- Таймаут соединения: 30 секунд, чтения: 5 минут (поддерживает длительную генерацию).
- Регистрируется в `MainActivity.onCreate()`.
- Веб-версия использует стандартный `fetch()` — плагин активируется только в нативном Android.

## Первый запуск

1. Откройте приложение в браузере или запустите APK на Android.
2. По умолчанию уже настроен **NuAdvi Proxy** (kreagenium.ru) — можно сразу начать чат с AI без дополнительной настройки.
3. Для использования собственного провайдера — перейдите на вкладку **Настройки** (шестерёнка), нажмите **Добавить** и выберите тип (OpenAI, OpenRouter и т.д.), укажите API ключ.
4. Заполните **Профиль** — укажите имя, параметры тела, выберите цели (включая пользовательские).
5. Перейдите на вкладку **Каталог** (продукты) — добавьте продукты и составьте блюда.
6. Всё готово — составляйте приёмы пищи из каталога в журнале, записывайте дневник, общайтесь с AI в чате.

## Как это работает

### Хранение данных
Все данные хранятся в **IndexedDB** браузера через библиотеку Dexie.js. 12 таблиц (7 версий миграций):
- `providers` — конфигурации LLM-провайдеров и API ключи
- `userProfile` — профиль пользователя (параметры, цели, ограничения)
- `foodEntries` — записи о приёмах пищи (структурированные: набор продуктов/блюд с весами)
- `foodProducts` — каталог продуктов (отдельные пищевые продукты)
- `dishes` — каталог блюд (составные блюда из продуктов с граммовками ингредиентов)
- `foodLibrary` — библиотека быстрых шаблонов приёмов пищи (legacy)
- `chatSessions` — сессии чата с AI
- `chatMessages` — сообщения чата
- `customGoals` — пользовательские цели питания
- `diaryEntries` — записи дневника (активность, самочувствие, давление)
- `settings` — настройки приложения (тема, язык, последний активный провайдер)
- `sleepLogs` — записи сна (дата, периоды сна с временем начала и конца)

### Каталог продуктов и блюд
Каталог хранится в двух таблицах IndexedDB:
- **Продукты** (`foodProducts`) — отдельные ингредиенты: яблоко, гречка, куриная грудка и т.д.
- **Блюда** (`dishes`) — рецепты, состоящие из продуктов с указанием веса каждого ингредиента в граммах.

При добавлении приёма пищи в журнале можно:
1. Выбрать отдельные продукты из каталога и указать вес.
2. Выбрать готовые блюда — их состав автоматически разворачивается в продукты.
3. Комбинировать продукты и блюда в одном приёме.

Структурированные данные приёма пищи преобразуются в текстовое описание при формировании промптов для LLM.

### LLM интеграция
Прямые HTTP-запросы к API провайдеров с ключами пользователя (формат OpenAI-compatible). Поддерживаются любые провайдеры с совместимым API:
- **OpenAI** (GPT-4o, GPT-4o-mini, ...)
- **OpenRouter** (DeepSeek, Claude, Llama, ...)
- **Alibaba DashScope** (Qwen, ...)
- **Ollama** (локальные модели, без интернета)
- **llama.cpp server** (локальные модели)
- **NuAdvi Proxy** (`kreagenium.ru/nuadvi`) — серверный прокси с fallback и приоритизацией, без API ключа
- Любые другие (вставьте свой Base URL)

Чат использует **SSE стриминг** (`stream: true`) — ответы появляются в реальном времени. Если провайдер не поддерживает стриминг — автоматически используется обычный запрос.

В Android APK запросы идут через **NativeHttpPlugin** — собственный Java-плагин Capacitor, использующий `HttpURLConnection`. Это решает проблемы WebView с CORS, mixed content и ограничениями на HTTP-запросы к локальным серверам (Ollama, llama.cpp). Таймаут чтения — 5 минут.

### Серверный прокси
При подключении к серверу (`https://kreagenium.ru/nuadvi/v1/chat/completions`) запросы маршрутизируются через Go-прокси:
1. **Алиас модели** (`gemma-4`, `gemini-2.5-fp`, `gigachat`) резолвится в список моделей из fallback-цепочки провайдеров
2. **SelectProviderCandidates** — acquire concurrency slots for all matching models, sorted by priority
3. **Handler** пробует кандидатов по порядку приоритета; при ошибке (429, таймаут) — освобождает слот и пробует следующего
4. **SOCKS5-прокси** — SSH-туннели через vpnjantit запускаются автоматически, health-check каждые 30с, автоперезапуск при падении
5. **SSE стриминг** pass-through — ответ передаётся клиенту в реальном времени; fallback если ошибка до отправки заголовков

Пользователи могут продолжать использовать собственные провайдеры и ключи — сервер опционален. По умолчанию приложение преднастроено на `NuAdvi Proxy` (kreagenium.ru) для удобства тестирования.

### Анализ еды
При анализе по фото происходит двухэтапный процесс:
1. **Vision-модель** описывает содержимое изображения.
2. Описание комбинируется с текстом пользователя (название блюда, вес) и передаётся в **промпт анализа питания**.

Результат парсится regex-ом для извлечения КБЖУ. Значения можно скорректировать вручную перед сохранением. Секция отладки позволяет увидеть промпты и ответ LLM.

### Контекстные промпты
Система автоматически определяет тему сообщения (ежедневный анализ, планирование, мотивация, обучение, проблемы со сном и т.д.) и подбирает соответствующий системный промпт, обогащённый:
- Данными профиля пользователя и целями питания (включая пользовательские).
- Сводкой питания за выбранный период (структурированные записи преобразуются в текст).
- Записями дневника (активность, самочувствие, давление) за выбранный период.
